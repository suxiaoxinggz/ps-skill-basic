# 逐屏比对检查清单

> Compare 阶段的目标是**找可见差异**，不是证明自己做得对。
> 所以必须同视口、同滚动位置、同状态；凭印象改会引入新偏差。

## 目录

1. 比对准备
2. 偏差分类（按修复优先级排序）
3. 分区逐项检查
4. 交互与状态
5. 收尾

---

## 1. 比对准备

- [ ] 源站与本地**同一视口**（先固定 1440×900，再补 375）。
- [ ] 两边都滚到**同一个 y 坐标**（用 section 地图的 top 值，不要目测）。
- [ ] 等字体、视频首帧、进场动画都稳定下来再截图（600–900ms）。
- [ ] 各截一张，命名对称：`src-y2400.png` / `clone-y2400.png`。
- [ ] 一次只比对一个 section——同时看三屏会不自觉地"脑补对齐"。

## 2. 偏差分类（按修复优先级）

**P0 结构**：缺整个 section、多/少图层、布局方向错（左右变上下）。
**P1 几何**：宽度比例、栅格列数、高度、sticky 偏移。
**P2 字体与换行**：字号、字重、字距、字体角色、换行位置。
**P3 资产**：图不对、裁切位置错、比例错、没灰度。
**P4 间距**：padding/margin 偏差 <8px。
**P5 动效**：时长、缓动、触发时机。

从 P0 往下修。修完一类重跑一次比对——修 P2 常常会带出新的 P1。

## 3. 分区逐项检查

### 全局件

- [ ] 导航高度、sticky 行为、滚动后是否加 blur/底色。
- [ ] 公告条文案与可关闭行为。
- [ ] 悬浮元素是不是**全页 fixed** 而不是 section 内 sticky
      （判断法：同一条 UI 出现在多个 section 截图里 ⇒ 它是 fixed 全局件）。
- [ ] 全站 accent 出现的位置与次数。

### Hero

- [ ] 视频是否在播、是否 muted/loop、有没有渐晕。
- [ ] 漂浮卡数量、位置、有没有压住标题。
- [ ] h1 行数与换行位置是否一致（字体不同必然不一致，但要判断是否是 font 替代导致的）。
- [ ] 输入条占位文案的打字机速度与文案内容。

### 滚动场景（最易错）

- [ ] 进入 / 中段 / 退出三个位置各截一张，看步进是否同步。
- [ ] sticky 元素的 `top` 偏移是否等于导航高度。
- [ ] 轨道总高度与步骤数是否匹配（n × 100vh）。
- [ ] 最后一步能不能走到底。
- [ ] 小屏是否正确降级为普通文档流。

### 卡片与纸面

- [ ] 白卡是否真的纯白、有没有深投影。
- [ ] 四角标记位置。
- [ ] 透视角度与方向。
- [ ] 图表图的裁切（有没有被拉伸变形）。

### 数据真实性

- [ ] 演示面板里的数字能否自圆其说（进度、计数、页码与显示内容一致）。
- [ ] 文案与源站逐字一致（对着 page-text.md 核，不是凭印象）。

## 4. 交互与状态

- [ ] 菜单展开 / 收起。
- [ ] tab / accordion 的展开态。
- [ ] 轮播的首尾边界。
- [ ] hover 态（对比 hover 前后的截图）。
- [ ] 移动端菜单。
- [ ] 反向滚动（sticky 场景退出时是否回位，这是最容易漏的）。
- [ ] 控制台无报错。

## 5. 收尾

- [ ] 跑项目的生产检查（lint + typecheck + build）。
- [ ] 375 / 768 / 1440 三档各查一次横向溢出。
- [ ] reduced-motion 下页面完整可读。
- [ ] **写一份残留差异清单**：每一项写明"差异是什么 / 为什么没消除 / 判定是否可接受"。
      主动声明比被用户发现好得多，而且"因为 X 所以选择 Y"的 trade-off 记录
      是下次复用时最值钱的部分。
